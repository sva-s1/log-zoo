# JSON (JavaScript Object Notation) Log Samples

This directory contains log samples in **JSON format**. JSON is a lightweight, text-based data interchange format that has become the de facto standard for structured logging in modern applications and systems.

## About JSON Logs

JSON format is widely adopted for logging because it:
- **Structured**: Provides hierarchical data organization with key-value pairs
- **Human-readable**: Easy to read and understand by both humans and machines
- **Parseable**: Native support in most programming languages and log analysis tools
- **Flexible**: Supports nested objects, arrays, and various data types
- **Standardized**: Well-defined specification (RFC 7159) ensures consistency

### JSON Format Characteristics

- **Objects**: Enclosed in curly braces `{}` with key-value pairs
- **Arrays**: Enclosed in square brackets `[]` for ordered lists
- **Data Types**: Supports strings, numbers, booleans, null, objects, and arrays
- **Encoding**: Typically UTF-8 encoded
- **Escaping**: Special characters are escaped using backslashes

## Common JSON Log Sources

JSON logs are frequently generated by:

- **Modern web applications** and microservices
- **Container orchestration platforms** (Docker, Kubernetes)
- **Cloud services** (AWS CloudWatch, Azure Monitor, Google Cloud Logging)
- **API gateways** and load balancers
- **Application frameworks** (Node.js, Python, Java Spring Boot)
- **Log aggregation systems** (ELK Stack, Fluentd, Logstash)
- **Security tools** and SIEM platforms
- **Database systems** (MongoDB, PostgreSQL JSON logs)
- **Message queues** and event streaming platforms

A typical JSON log entry might look like this:

```json
{
  "timestamp": "2025-07-25T08:00:01.123Z",
  "level": "INFO",
  "service": "user-authentication",
  "message": "User login successful",

  "metadata": {
    "trace_id": "abc123def456",
    "span_id": "789ghi012jkl",
    "environment": "production"
  }
}
```

## JSON Log Formats

### Single-Line JSON (JSONL/NDJSON)
Each log entry is a complete JSON object on a single line:
```json
{"timestamp":"2025-07-25T08:00:01Z","level":"INFO","message":"Request processed"}
{"timestamp":"2025-07-25T08:00:02Z","level":"ERROR","message":"Database connection failed"}
```

### Multi-Line JSON
Each log entry is formatted with proper indentation (less common for logs):
```json
{
  "timestamp": "2025-07-25T08:00:01Z",
  "level": "INFO",
  "message": "Request processed"
}
```

### JSON Arrays
Multiple log entries contained within a JSON array:
```json
[
  {"timestamp":"2025-07-25T08:00:01Z","level":"INFO","message":"First event"},
  {"timestamp":"2025-07-25T08:00:02Z","level":"WARN","message":"Second event"}
]
```

## Common JSON Log Fields

Standard fields often found in JSON logs:

- **timestamp**: Event occurrence time (ISO 8601 format recommended)
- **level/severity**: Log level (DEBUG, INFO, WARN, ERROR, FATAL)
- **message**: Human-readable description of the event
- **logger/service**: Source component or service name
- **thread/process**: Execution context information
- **trace_id/correlation_id**: Distributed tracing identifiers
- **user_id**: Associated user identifier
- **session_id**: Session tracking information
- **request_id**: Unique request identifier
- **environment**: Deployment environment (dev, staging, prod)

## Parsing Considerations

When working with JSON logs:

1. **Line Format**: Determine if logs are single-line JSON (JSONL) or multi-line
2. **Schema Validation**: Understand the expected JSON structure and required fields
3. **Data Types**: Handle proper type conversion for timestamps, numbers, and booleans
4. **Nested Objects**: Parse hierarchical data structures appropriately
5. **Array Handling**: Process arrays of values or nested objects
6. **Error Handling**: Gracefully handle malformed JSON entries
7. **Memory Usage**: Consider streaming parsers for large JSON log files
8. **Encoding**: Ensure proper UTF-8 character handling

## Transport Methods

JSON logs are typically:
- **Streamed** to log aggregation systems (Elasticsearch, Splunk)
- **Sent** via HTTP/HTTPS to log collection endpoints
- **Published** to message queues (Kafka, RabbitMQ, AWS SQS)
- **Written** to files for batch processing
- **Forwarded** through log shippers (Filebeat, Fluentd, Vector)
- **Stored** in cloud logging services (CloudWatch, Stackdriver)

## Best Practices for JSON Logs

1. **Consistent Schema**: Use consistent field names and structures across services
2. **Timestamp Standards**: Use ISO 8601 format for timestamps
3. **Structured Messages**: Prefer structured data over free-form text messages
4. **Avoid Deep Nesting**: Keep object hierarchy reasonably flat for easier querying
5. **Field Naming**: Use snake_case or camelCase consistently
6. **Sensitive Data**: Never log passwords, tokens, or other sensitive information
7. **Performance**: Consider log volume and parsing performance impact
